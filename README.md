# app.tak.nz

The server list and landing page for the TAK.NZ mobile app, published with GitHub Pages at <https://app.tak.nz>.

| URL | What it is |
|---|---|
| `https://app.tak.nz/` | Landing page (store links will go here) |
| `https://app.tak.nz/v1/servers.json` | The list of servers the app offers on first run |

## Why this exists

The first screen of the mobile app lists the servers a user can connect to. Out of the box that list comes from upstream CloudTAK's own registry. This repository replaces it, so the TAK.NZ app shows TAK.NZ servers. Users can still type any server URL by hand.

## Add or change a server

1. Edit [`servers.json`](servers.json):

   ```json
   { "name": "TAK.NZ Demo", "url": "map.demo.tak.nz", "logo": "logos/taknz.png" }
   ```

   - `name` is what users see. It must be unique.
   - `url` is the host name only: lowercase, no `https://`, no path. The app adds `https://`, and a server can never be listed over plain `http`.
   - `logo` is optional: a PNG under `logos/`, at most 64 KB. About 128 x 128 px is plenty. It is embedded in the list, which the app downloads on first run, so keep it small.
2. Open a pull request. CI validates the file and fails with a message if anything is wrong.
3. Merging to `main` publishes the change. The list is cached for up to 10 minutes.

Run it locally with Node 20 or later:

```bash
npm test
npm run build   # validates servers.json and writes dist/
```

## Who can change this list

Whoever can merge here decides where users sign in, so a bad entry is a phishing risk. Protect `main` (require a pull request and a review) and keep write access small.

## File format

`/v1/servers.json` is generated by `scripts/build.mjs`:

```json
{
  "version": 1,
  "generatedAt": "2026-01-01T00:00:00.000Z",
  "servers": [
    { "name": "TAK.NZ Demo", "url": "map.demo.tak.nz",
      "logo": { "filename": "taknz.png", "mediaType": "image/png", "base64": "..." } }
  ]
}
```

This matches the format of upstream CloudTAK's registry, so the app reads it unchanged. Installed apps keep calling `/v1/` for years, so never change the meaning of this file. A breaking change goes in a new `/v2/` and `/v1/` keeps being served.

## Hosting

- **Pages source:** GitHub Actions (`.github/workflows/pages.yml`).
- **Custom domain:** `app.tak.nz`, via a DNS `CNAME` record pointing to `tak-nz.github.io`.
- **CORS:** GitHub Pages sends `Access-Control-Allow-Origin: *`, which the app needs to read the list from a different origin.
