# app.tak.nz

The server list and landing page for the TAK.NZ mobile app, published with GitHub Pages at <https://app.tak.nz>.

| URL | What it is |
|---|---|
| `https://app.tak.nz/` | Download page, styled as part of tak.nz |
| `https://app.tak.nz/v1/servers.json` | The list of servers the app offers on first run |

## Why this exists

The first screen of the mobile app lists the servers a user can connect to. Out of the box that list comes from upstream CloudTAK's own registry. This repository replaces it, so the TAK.NZ app shows TAK.NZ servers. Users can still type any server URL by hand.

## Add or change a server

1. Edit [`servers.json`](servers.json):

   ```json
   { "name": "TAK.NZ Demo", "url": "map.demo.tak.nz", "logo": "logos/taknz.png" }
   ```

   - `name` is what users see. It must be unique.
   - `url` is the host name only: lowercase, no `https://`, no path. The app adds `https://`, and a server can never be listed over plain `http`.
   - `logo` is optional: a PNG under `logos/`, at most 64 KB. About 128 x 128 px is plenty. It is embedded in the list, which the app downloads on first run, so keep it small.
2. Open a pull request. CI validates the file and fails with a message if anything is wrong.
3. Merging to `main` publishes the change. The list is cached for up to 10 minutes.

Run it locally with Node 20 or later:

```bash
npm test
npm run build   # validates servers.json and writes dist/
```

## Who can change this list

Whoever can merge here decides where users sign in, so a bad entry is a phishing risk. Protect `main` (require a pull request and a review) and keep write access small.

## File format

`/v1/servers.json` is generated by `scripts/build.mjs`:

```json
{
  "version": 1,
  "generatedAt": "2026-01-01T00:00:00.000Z",
  "servers": [
    { "name": "TAK.NZ Demo", "url": "map.demo.tak.nz",
      "logo": { "filename": "taknz.png", "mediaType": "image/png", "base64": "..." } }
  ]
}
```

This matches the format of upstream CloudTAK's registry, so the app reads it unchanged. Installed apps keep calling `/v1/` for years, so never change the meaning of this file. A breaking change goes in a new `/v2/` and `/v1/` keeps being served.

## The download page

`site/index.template.html` is the page. It has the tak.nz logo bar (no menu), the headline, an optional picture of the app on two phones, and the App Store and Google Play badges.

**Store links.** Until the app is published the badges are shown dimmed and are not clickable, with a note saying so. When it is published, put the links in [`site.json`](site.json) (https only) and merge:

```json
{ "appStore": "https://apps.apple.com/app/id...", "googlePlay": "https://play.google.com/store/apps/details?id=nz.tak.app" }
```

Each badge becomes a link on its own as soon as its link is set, and the "not in the stores yet" note disappears when either is.

**Phone picture.** Take two portrait screenshots on a phone, put them in `screens/` as `1.png` and `2.png`, and run `scripts/make-phone-mockup.sh`. It writes `site/images/app-screens.webp`, and the page shows it automatically once that file exists (see `screens/README.md`). Until then the section is left out rather than showing a placeholder.

The badges in `site/images/badges/` are the official App Store and Google Play artwork. Follow Apple's and Google's badge guidelines if you change them.

## Keeping the landing page in step with tak.nz

Visitors should not notice they have left <https://tak.nz>, so the landing page does not carry its own design:

- The **header, mobile menu and footer** are copied from the live tak.nz home page at build time (`scripts/site.mjs`), so a new menu item or footer link on the website shows up here on the next build.
- The **stylesheet, scripts, fonts, logo, icons, photo and hero video** are loaded from tak.nz itself.
- Only the page content is written here, in `site/index.template.html`. The header keeps just the logo: the site menu, the Sign Up / Login buttons and the mobile menu are removed on purpose.

The site is rebuilt on every push, weekly (Mondays), and on demand from the Actions tab. To pick up a website change at once, run the workflow manually.

If tak.nz changes shape so that its header, menu or footer can no longer be found, the build **fails** and the last published page stays online. Fix `scripts/site.mjs` when that happens. `scripts/fixtures/taknz-home.html` is a saved copy of those blocks for the tests. Refresh it if the website's markup changes.

To build without network access, point `TAKNZ_PAGE` at a saved copy of the tak.nz home page:

```bash
TAKNZ_PAGE=scripts/fixtures/taknz-home.html npm run build
```

## Hosting

- **Pages source:** GitHub Actions (`.github/workflows/pages.yml`).
- **Custom domain:** `app.tak.nz`, via a DNS `CNAME` record pointing to `tak-nz.github.io`.
- **CORS:** GitHub Pages sends `Access-Control-Allow-Origin: *`, which the app needs to read the list from a different origin.
